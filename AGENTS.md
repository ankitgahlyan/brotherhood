# Instructions

- **Be concise.** Only change code directly related to the current task; leave unrelated parts untouched.
- **Reuse** existing types, functions and components. Search before creating a new one.
- **No new libraries.** Use existing dependencies only. If a task truly can't be done without a new library, stop and explain why.
- **Only** write tests when directly prompted to do so.

- **After your solution:**
  1. Think like on a code review and identify any shortcomings.
  2. Fix those issues. Repeat review-fix cycle until you are sure about code quality.
  3. Present the improved result.

- **When deeper debugging is needed:**
  1. Outline clear, step-by-step debugging instructions in your output.
  2. Remove any temporary debug code once the issue is resolved.

- when exploring or editing files, if you find any inconsistencies or bugs, point them to me after current request is complete.
- **User is the Source of Truth on Discrepancies:** Whenever there is any discrepancy or conflict between tests, code, docs, READMEs, frontend, or smart contracts, **the user is the single source of truth**. Never silently assume one side is right or alter contract/test semantics to make a check pass — stop and consult the user (e.g. via `ask_question` / `/grill-me`) to confirm the intended behavior first.
- **Codify All Failures into Rules:** Whenever a bug, test failure, runtime error, or framework violation (e.g. React infinite re-render loops, TVM execution errors, serialization mismatch, selector instability) is identified and resolved, formulate and append the underlying invariant as an explicit rule under the relevant section of `AGENTS.md` to prevent future regressions.
- **No Redundant Post-Edit Lint, Format, Typecheck, or Test Runs (Rely on Pre-Commit Hook):** Do **not** manually run `bun format`, `bun lint`, `bun typecheck`, `bun test`, or `acton test` after making code changes. The repository's pre-commit hook (`.githooks/pre-commit` → `node scripts/pre-commit-tests.mjs --staged`) automatically runs Prettier formatting, ESLint (`--fix`), Tolk `acton fmt` / `acton check` / `acton test`, scoped workspace TypeScript typechecks, and affected unit tests on all staged files during `git commit`. Running these checks manually after edits is redundant and wastes time; instead, commit directly and only fix and re-commit if the pre-commit hook fails.
- **Full-Stack Blast-Radius & Cross-Layer Sync Checklist:** Every contract or frontend modification must trace and update every affected downstream layer before completion:
  1. **Wrappers, Tests & Scripts:** When `contracts/src/**` structs, messages, getters, constants, or storage change, regenerate `wrappers-ts/*.gen.ts` (`acton build && acton wrapper`), and update `contracts/tests/**` and `contracts/scripts/**` (including gas/timing constants and file/test names when a concept is renamed).
  2. **Hydration, Payload Builders & Config:** Sync in-memory BOC hydration (`apps/wallet/src/lib/brotherhood/account-hydrator.worker.ts`), domain types (`types.ts`), payload builders (`contract-builders.ts`), and protocol/gas constants (`config.ts`, `use-brotherhood-transaction.ts`).
  3. **Transaction History & Trace Decoders:** Whenever any message opcode (`struct (0x...)`) or error code (`enum Errors`, `enum FollowingErrors`) is added, renamed, or modified in `contracts/src/**/*.tolk`, sync `KNOWN_OPCODES` & `FRIENDLY_OPCODE_TITLES` in `apps/wallet/src/core/utils/payload.ts`, and `TVM_EXIT_CODES`, `getContractContextBadge`, & `FI_STRUCT_NAMES` in `apps/wallet/src/features/transactions/utils/map-transaction-row.ts`.
  4. **UI Flows, Naming & Domain Glossary:** Audit all consuming tabs, modals, search/lookup views, hooks, file/test names, and `CONTEXT.md` across `apps/wallet/src/` and `packages/` so every affected surface reflects the change with zero stale terminology or partial state.

#### Contract rules

- separate struct/msg files for each contract instead of unnecessarily bloating other contracts and common file for common structs/msg.
- report any circular dependency issues.
- use fail-fast approach, use assertions early at msg entry into contracts.
- **Deterministic Proxy Bytecode & Storage Migration:** Minimal proxy contracts (`BaseFiWallet`, `BasePersonalMinter`, `BaseLocation`, `BaseFollowing`) used for deterministic child address derivation must never self-import their own compiled bytecode artifact (preventing compiler cycles) and must never store target contract bytecode or serialize full target storage structs (`FiWalletStore`, `PersonalStore`, `LocationStore`, `FollowingStore`) inside the proxy. Storage migration and initial message handling must reside in the target upgraded contract (`FossFiWallet`, `PersonalMinter`, `Location`, `Following`) via `@method_id(2223)` (`migrate*FromBase`) rather than bloating the proxy. The proxy verifies the sender and target code cell, executes `setCodePostponed`, replaces `c3` via `setTvmRegisterC3`, and invokes migration via `@method_id(2223)`. Target contracts must preserve `@method_id(2223)` in their compiled code dictionary against dead-code elimination. Whenever any `Base*.tolk` proxy is modified, its `code_boc64` must be synced to its `base-*-code.tolk` helper and `wrappers-ts/Base*.gen.ts`.
- **Acyclic Deterministic Proxy & Method 0 Re-entry:** To prevent bytecode inflation and preserve a truly minimal proxy footprint across all personal wallets, `BasePersonalWallet` must never embed target contract bytecode (`PersonalWallet.code`). Instead, the deployment/onboarding message (`InternalTransferStep`) dynamically delivers `latestWalletCode`, strictly gated by either a 1 GRAM (`grams("1")`) deploy signal or a credit purchase (`msg.transferredAsCredit`). `BasePersonalWallet` asserts `((msg.jettonAmount == grams("1")) | msg.transferredAsCredit) & (msg.latestWalletCode != null)` (throwing `Errors.NotOnboardedWallet`), dynamically installs the code via `setCodePostponed`, replaces `c3` via `setTvmRegisterC3`, and executes method 0 re-entry (`0 CALLDICT`). Whenever `BasePersonalWallet.tolk` is modified, `getBasePersonalWalletCode()` in `contracts/src/personalMinter/personal-wallet-code.tolk` and `wrappers-ts/BasePersonalWallet.gen.ts` must be synchronized with `build/BasePersonalWallet.json`'s `code_boc64`, otherwise `PersonalMinter` will deploy stale proxy bytecode and fail with `Cannot execute unknown get method get_wallet_data (97026)`.
- **RichBounce vs RichBounceOnlyRootCell Reference Preservation Invariant:** When dispatching messages whose bounce recovery handler inspects child cell references on `RichBounceBody.originalBody` (such as `MintNewJettons.internalTransferMsg: Cell<InternalTransferStep>` in `FossFiWallet.onBouncedMessage`), the sender must use `BounceMode.RichBounce` rather than `BounceMode.RichBounceOnlyRootCell`. `RichBounceOnlyRootCell` strips all cell references from `originalBody`, causing `.load()` on any `Cell<T>` field to abort with TVM cell underflow.
- **3-Decimal Fixed-Point Credit Multiplier & Manual `creditNeed` Invariant:** `FiWalletStore.multiplier` (`uint16`) is scaled by `MULTIPLIER_SCALE = 1000` (`1000 = 1.000x`, supporting `0.001x` to `65.535x`). `creditNeed` is never auto-replenished on `Payback` and must only be modified manually via `SetLoanRequirement`. When `store.multiplier <= 1000`, `creditMaturity` may be `0` (instant maturity for two-way liquid swaps); when `store.multiplier > 1000`, `SetLoanRequirement` requires `effectiveMaturity > blockchain.now()` and `InternalTransferStep(transferredAsCredit = true)` rejects `BuyCredit` once `blockchain.now() >= store.creditMaturity`. Frontend consumers must normalize raw on-chain multipliers via `normalizeOnchainMultiplier` (`raw / 1000`) and encode user inputs via `encodeOnchainMultiplier` (`BigInt(Math.round(val * 1000))`).
- **Prohibition of Custom Public On-Chain Libraries (TON Global Version 15+):** Since TON network upgrade Global Version 15 (ConfigParam 8), publishing public libraries via `SETLIBCODE(code, 2)` or `acton library publish` from regular smart contract accounts is prohibited by protocol validators and aborts in the TVM Action phase with `action_result_code = 46` (_"Library change action is prohibited"_). Only special masterchain system accounts (elector, config) may publish public libraries. Contracts must never rely on deploying custom public masterchain libraries on testnet or mainnet; code reuse and deterministic address derivation must strictly use the deterministic minimal proxy pattern (`BaseFiWallet`, `BasePersonalWallet`) or embed code directly.
- **Personal Token & Wallet Upgradability Invariants:** Both `PersonalMinter` (`PersonalStore`) and `PersonalWallet` (`PersonalWalletStore`) contracts maintain monotonic schema versions (`version: uint10 = 1`). In contracts with trailing `storage.save()` at the end of `onInternalMessage`, message handlers (such as `Upgrade`) must never execute an early `return;` without persisting updated state, ensuring version bumps and mutated fields are committed to contract storage. Authenticators for `HotUpgrade` (`additionalData: cell?`, `code: cell`) must verify `in.senderAddress == storage.minterAddress` (or minter admin / parent address) without referencing `msg.sender` (which is not part of the `HotUpgrade` message struct). Peer upgrades via `Upgrade` must strictly verify `in.senderAddress == autoAddrPriWallet(msg.sender).calculateAddress()`, rejecting calls from unverified arbitrary accounts and wallet owners alike.
- **Instant FiWallet Upgrade Propagation & Gas Reservation Invariant:** In `FossFiWallet`, when an `Upgrade` message is received, upgrade propagation across invitees (`maps.invited`) must strictly execute when `store.version < msg.walletVersion` (only on monotonic bump) to eliminate broadcast loops and gossip storms. Each forwarded message carries 0.1 TON with `SEND_MODE_PAY_FEES_SEPARATELY | SEND_MODE_IGNORE_ERRORS`. Before dispatching to each invitee, the contract must verify `contract.getOriginalBalance() >= safetyReserve + forwardCost` (0.2 TON safety reserve + 0.1 TON forward cost) and safely halt iteration if funds are insufficient, preventing contract bricking from gas exhaustion. In incoming `onInternalMessage`, `FossFiWallet` must accept empty messages (`in.body.remainingBitsCount() == 0`) with an early return to receive plain TON top-ups.
- **DNS Item 1023-Bit Storage Cell Invariant:** In `DnsItem` (`ItemStorageInitialized`), storing extra configuration addresses directly in the root storage cell causes cumulative bits to exceed 1023 bits (256 + 267 + 267 + 64 + 267 = 1121 bits) once ownership is assigned (`ownerAddress != null`), triggering TVM `exit_code = 8` (_"Cell overflow"_). All extension fields (such as `fiMinterAddress`) must be isolated in a dedicated reference sub-cell (`extra: Cell<ItemExtra>? = null`), strictly preserving root cell bit count $\le 855$ bits across all operational states while utilizing the 4th cell reference slot (`content`, `domain`, `auction`, `extra`).
- **DNS Auction Finalization vs Legacy Auto-Completion:** In `DnsItem`, legacy TON DNS auto-completes auctions on any incoming internal message after `auctionEndTime` by sending balance to `collectionAddress` and zeroing `storage.auction = null`. For `.bro` FI auctions (`storage.getFiMinterAddress() != null`), this auto-completion must strictly be guarded and bypassed so that `FinalizeAuction` can unpack the winning bid, transfer domain ownership to the winner, and dispatch `DnsAuctionFinalized` to `FossFi` minter to burn winning FI tokens and route 0.5 TON to Treasury.
- **Acton Test Time Simulation & Storage Fee Invariant:** In Tolk emulation tests, calling `testing.treasury()` or `newActor()` before initializing simulated time via `testing.setNow(AUCTION_START_TIME + 100)` creates accounts at unix timestamp 0; advancing time by 52 years in subsequent `setNow` causes TVM to abort with `cannot create storage phase of a new transaction for smart contract` (`exit_code = -669`) due to catastrophic storage fee calculation over 1.65 billion elapsed seconds. `testing.setNow()` must strictly execute before instantiating any actor or treasury accounts.
- **Centralized Constants & Non-Transitive Tolk Import Scoping:** All global protocol constants, emission values, auction timing, and deployment/emulation addresses (`FI_ADDRESS`, `BRO_COLLECTION_RESOLVER`, `BRO_TREASURY_ADDRESS`, `DAO_PROXY_ADDRESS`, `ZERO_ADDRESS`) must reside strictly in single sources of truth: `contracts/src/common/constants.tolk` for smart contracts and `apps/wallet/src/lib/brotherhood/config.ts` for the frontend. In Tolk, import scoping is strictly file-scoped: when file A imports file B, symbols defined in file B are not transitively re-exported to file C that imports file A. Any contract, script, or test file requiring global constants must directly import `@contracts/common/constants` rather than relying on intermediate re-exports.
- **Unified Global Exit Codes (`enum Errors`) & Direct Error Importing:** In Tolk, all top-level `enum` declarations share the project compilation unit namespace. Defining multiple `enum Errors` across subpackages (such as `contracts/src/dns/errors.tolk` and `contracts/src/common/errors.tolk`) causes compiler symbol redefinition failures (`error[C001]: redefinition of symbol, previous was at ...`). All custom exit codes across domain contracts must be declared exclusively within the single centralized `enum Errors` in `contracts/src/common/errors.tolk` with domain disambiguation where exit codes differ (e.g. `DnsNotOwner = 401` vs `NotOwner = 73`, `DnsIncorrectSender = 424` vs `IncorrectSender = 700`). Due to non-transitive Tolk imports, any contract using `Errors.<Name>` must directly `import "@contracts/common/errors"`.
- **DnsItem Owner Guard vs Forced Non-Null Assertion:** In `DnsItem.tolk`, messages that require domain ownership (`TransferOwnership`, `EditContent`, `ChangeDnsRecord`, `FillUp`) must strictly check `storage.ownerAddress != null && in.senderAddress == storage.ownerAddress` instead of force-unwrapping `storage.ownerAddress!`. Force-unwrapping a null owner (which occurs while an English auction is active or awaiting finalization) crashes with TVM exit code 7 (Type check error / null dereference) rather than throwing the semantic `Errors.DnsNotOwner` or `Errors.OnlyOwnerCanChangeDns`.
- **Tolk Map Type-Alias Custom `packToBuilder` vs `.toCell()` Decay Invariant:** When a type alias over `map<K, V>` defines a custom `packToBuilder` / `unpackFromSlice` (such as `type DnsRecords = map<uint256, cell>` with an 8-bit `0x00` TEP-64 prefix), mutating a variable via `map` methods (`.set()`, `.delete()`) or initializing with `= []` causes Tolk's type inference to decay the expression's static type to the underlying `map<K, V>`. Calling `.toCell()` directly on the decayed variable invokes built-in `map.packToBuilder` (1-bit dict flag) instead of `DnsRecords.packToBuilder` (8-bit prefix + 1-bit dict flag), causing subsequent `Cell<DnsRecords>.load()` calls to abort with TVM `exit_code = 9` (_"Cell underflow"_). Always serialize custom-packed map aliases through an explicit helper (`dnsRecords.toDnsRecordsCell()`) that directly invokes `self.packToBuilder(mutate b)`.
- **Deterministic `StateInit` vs Dynamic `blockchain.now()` Timestamp Invariant:** In TON, a contract's address is `sha256(StateInit(code, data))`. Passing dynamic timestamps (`blockchain.now()`) into initial storage (`fromStorage(...)`) during deployment mutates `StateInit.data` on every second, producing a different contract address on every emulation or live broadcast run. Any contract whose address must be deterministic (such as `DnsCollection`) must initialize timestamp fields to `0` in `StateInit.data` (`deploymentTime: 0`) and populate `blockchain.now()` lazily on-chain inside the initial deployment message handler (e.g. `FillUp { queryId: 1 }` setting `storage.deploymentTime = blockchain.now()` when `storage.deploymentTime == 0 && msg.queryId > 0`).
- **Acton Test & Script `build()` vs Gitignored `@gen/*.code` Invariant:** `acton build` only generates `gen/<Contract>.code.tolk` for contracts explicitly listed in `depends = [...]` in `Acton.toml`, and never deletes stale files from the gitignored `gen/` directory when a dependency is removed from `Acton.toml`. Tests (`contracts/tests/`) and scripts (`contracts/scripts/`) must always use `build("<Contract>")` (from `@acton/build`) rather than importing `@gen/<Contract>.code`, preventing CI failures when `gen/` is built fresh on GitHub Actions.
- **TEP-64 Off-Chain Collection Content, On-Chain Item Metadata & TEP-81 `get_auction_info` Stack Invariant:** In `DnsCollection`, off-chain `collectionContent` must serialize `0x01` + ASCII URI inline in the root cell (`makeBroOffchainContentCell`), never using `uri.prefixWith01().toCell()` which creates a double-wrapped 0-bit root cell with a child ref that Toncenter v3 and TonAPI reject (`collection: null`). In `DnsItem`, `initialContent` and `ChangeDnsRecord` must always populate and preserve on-chain TEP-64 dictionary keys `"name".sha256()`, `"image".sha256()`, and fallback `"description".sha256()` so NFT indexers and explorers display domain artwork even when `"uri"` stores a SimpleX/Briar contact link. Furthermore, `ItemStorageInitialized.unpackAuction` must return `createAddressNone() as address` (`b{00}` slice) rather than TVM `null` when `auction == null` so `get_auction_info()` satisfies TEP-81 `(slice, int, int)` ABI decoders on Tonviewer/TonAPI.
- **TypeScript Wrapper `CodeCell` Synchronization & DNS `RichBounce` Recovery Invariant:** `[wrappers.typescript]` (`output-dir = "./wrappers-ts"`) in `Acton.toml` must remain enabled so `acton wrapper` keeps `wrappers-ts/*.gen.ts` (`CodeCell` bytecode) in sync with compiled contracts (`build/*.json`). Stale `DnsItem.CodeCell` in `wrappers-ts/DnsItem.gen.ts` causes `deriveDnsItemAddress` in the frontend to compute pre-upgrade `StateInit` addresses that do not match the `nftItemCode` deployed by `DnsCollection` on-chain. Furthermore, because `BidBroDomain` and `RenewBroDomain` exceed 256 bits (`op(32) + queryId(64) + address(267) + fiAmount(coins) > 256 bits`), `FossFiWallet` and `FossFi` must dispatch them with `BounceMode.RichBounce` and handle `0xfffffffe` (`RichBounceBody`) in `onBouncedMessage` so bounced bids or renewals restore `totalSupply` and refund `fiAmount` to the user's `FiWallet` instead of aborting with TVM `exit_code = 63`.
- **Acton `scripts.wallet()` in `--fork-net` vs `--net` Broadcast Mode Invariant:** In Acton scripts, `scripts.wallet(name)` only resolves real wallet addresses from `wallets.toml` / `global.wallets.toml` when `ffi.isBroadcasting()` is true (`--net <network>`); under `--fork-net <network>` (emulation without `--net`), `scripts.wallet(name)` returns a synthetic local treasury (`testing.treasury(name).address`). Scripts that interact with sender-authenticated contracts (such as `deploy-personal.tolk` and `destroy-personal.tolk`) must allow overriding the sender address via `promptJettonAddress("PERSONAL_ADMIN_ADDRESS", ..., wallet.address)` and dispatch messages from that resolved address (`net.send(admin, ...)`), preventing `Errors.IncorrectSender` (`exit_code = 700`) during `--fork-net` emulation.

### In-Memory Contract State Ingestion & Batching Rules

- **Universal Batch Account Ingestion:** Prefer batch querying `accountStates?include_boc=true` in chunks of 30 over dispatching individual `runGetMethod` calls. Deserialize contract storage in-memory using pure Tolk wrapper functions (`FiWalletStore.fromSlice`, `PersonalStore.fromSlice`, `LocationStore.fromSlice`, etc.).
- **Zero Getter Fallback on Code Hash Mismatch:** When an account's `code_hash` does not match the latest release compiled hash and in-memory `fromSlice` fails, never fall back to on-chain `runGetMethod` calls (as updated wrapper tuple parsers will throw anyway). Instead, flag `isOutdatedCode: true`, serve cached state if available, and prompt the user/member with an upgrade banner.
- **No Frontend Code Hash Updates Without Live-Net Upgrade:** Never update contract code hashes in the frontend (`CONTRACT_CODE_HASHES` in `apps/wallet/src/lib/brotherhood/account-hydrator.worker.ts`) for contracts that have not actually had their upgrade script broadcast on a live network (`--net testnet` / `--net mainnet`, not `--fork-net` emulation). Minor source refactors (such as constant renames or shared file imports) may alter compiled bytecode hashes of untouched contracts without warranting an on-chain upgrade; updating their frontend code hashes without a live upgrade would falsely flag live on-chain contracts as `isOutdatedCode: true`.
- **Off-Chain Address Derivation:** Derive child contract addresses deterministically off-chain using minimal proxy wrappers' `fromStorage` (`BaseFiWallet.fromStorage`, `BasePersonalMinter.fromStorage`, `BasePersonalWallet.fromStorage`, `BaseLocation.fromStorage`, `BaseFollowing.fromStorage`) to allow querying parent and child contract states concurrently in the very first batch request without drifting on target contract upgrades.
- **Silent FiWallet Auto-Funding Invariant:** Upon hydration in the frontend (`useTrackedAddressesSync`), the client evaluates the on-chain balance of all saved wallets' FiWallets and circle invitee FiWallets. Any contract with balance `< 2 TON` (`2_000_000_000n`) is automatically funded with 2 TON silently without user confirmation modals. Auto-funding strictly preserves a 0.5 TON (`500_000_000n`) reserve in the active wallet for user operations (`maxRecipients = Math.floor((activeBalance - 0.5 TON) / 2.05 TON)`), batches payments via `createTransferMultiTonTransaction`, and maintains a session-level de-duplication cache (`Set<string>`) to prevent redundant transfers across background hydration ticks.
- **TEP-81 TON DNS Subdomain Extraction Invariant:** When querying authoritative TON DNS zone resolvers (e.g. `.ton`, `.t.me`, `.vip`, `.grm`) via `dnsresolve`, the argument passed to the resolver must be only the encoded subdomain prefix without the zone suffix (e.g., `'tolya'`, NOT `'tolya.ton'`). Passing the full domain including the TLD suffix to root zone resolvers violates TEP-81 and aborts TVM execution with exit code -13. Non-existent domains, unallocated records, or inactive resolvers must be caught and treated as unresolved (`undefined`) rather than throwing unhandled runtime exceptions.
- **FiWallet Invitee Address Derivation Invariant:** In `FossFiWallet.tolk`, `maps.invited` directly maps invitee addresses to their deployed/bound `FiWallet` addresses (not raw owner addresses). Hydration loops and auto-funding procedures must never invoke `getFiWalletAddress(inviteeAddr)` on entries already retrieved from `maps.invited`, which would calculate the FiWallet of a FiWallet, routing funds to non-existent child contracts. Furthermore, `baseFiWalletCodeCell` in frontend wrappers (`base-fi-wallet-code.ts`) must remain synchronized with the compiled `build/BaseFiWallet.json` BOC hash.
- **Exclusive Brotherhood (.bro) DNS Scoping:** All DNS resolution across the application must strictly scope to `.bro` domains resolving through the authoritative `BRO_COLLECTION_RESOLVER`. All legacy and external root zone resolvers (`.ton`, `.t.me`, `.vip`, `.grm`) must be omitted from input validation, resolvers, and placeholders to prevent TVM zone resolver exceptions and domain spoofing.
- **`.bro` DNS Owner Fallback & Zero-Getter BOC Resolution Invariant:** Newly minted `.bro` domains (including `genesis.bro` and auction-finalized or admin-registered domains) initialize with an empty `DnsRecords` dictionary (`8`-bit `0` tag prefix + `1`-bit `0` empty dict flag). `resolveAddressByDomain` and `useDomainLookup` must deserialize `DnsItem` and `DnsCollection` storage directly in-memory via `batchFetchAccountStates` (`parseDnsItemAccountState`, `fetchBroCollectionState`) rather than invoking `runGetMethod('dnsresolve')`, resolving to the explicit `"wallet"` DNS record (`sha256("wallet")`) when present and falling back to the NFT `ownerAddress` when no `"wallet"` record is set and the domain is not expired (`now <= lastFillUpTime + ONE_YEAR_SEC`). Furthermore, `useMyDomains` must never short-circuit on an empty local `useDnsStore`; it must auto-discover owned `.bro` domains on-chain (via Toncenter v3 `/nft/items` for `BRO_COLLECTION_RESOLVER` plus deterministic `genesis.bro` check) and hydrate `walletRecord` and ownership via `batchFetchAccountStates`.
- **Single-Call Input Resolution, 0ms Local Hit, 3s API Debounce & 1-Char Handle Support Invariant:** In `useAddressUsernameResolution` and recipient/granter inputs, handles and `.bro` domains of `>= 1` character (`/^[a-zA-Z0-9_\- ]{1,40}$/`) must be supported. Local cache hits (`useContactBookStore` for `.bro` domains and `contact-storage` for `@username` mappings, kept strictly separate) must resolve synchronously in `0ms` with zero network calls. On a local cache miss, on-chain resolution must wait `3000ms` (3 seconds) after typing stops and dispatch strictly **one** `batchFetchAccountStates` BOC request (`resolveAddressByDomain` for domains/handles saving to `useContactBookStore`, or `getFiWalletState` for direct addresses saving to `contact-storage`), never firing secondary `getBroDomainAuctionInfo` (`runGetMethod`) or duplicate `getFiWalletStateByContractAddress` calls. Additionally, `CommentField` must only query `resolveRecipientPublicKey` when `comment.trim()` is non-empty.
- **Session/TTL Cache for `batchFetchAccountStates`, `useMyDomains`, and `loadUserNfts` & Address-Normalized `.bro` NFT Enrichment:** `batchFetchAccountStates`, `useMyDomains`, and `loadUserNfts` must maintain module-level session/TTL caches (5-minute TTL + in-flight request deduplication) so switching tabs never re-fetches `/accountStates` or `/nft/items`, while explicit hard refresh (`RefreshButton` / `force: true` / `refreshNfts`) bypasses the TTL cache. When merging indexer NFTs (`userNfts`) with locally tracked `.bro` domains (`ownedBroDomains`), addresses must be compared via canonical raw address (`Address.parse(addr).toRawString()`) rather than string equality (`EQ...` vs `kQ...`) and enriched via `mergeAndEnrichBroNfts` with `BRO_DEFAULT_IMAGE_URI`.
- **`useMyDomains` LocalStorage Address Migration, Auction Discovery & Non-Existent Pruning Invariant:** In `useMyDomains`, every persisted `.bro` domain in `useDnsStore` (`localStorage` key `dns_domains_store`) must first have its `nftAddress` re-derived via `deriveDnsItemAddress(collectionAddr, d.name, testOnly)` so domains persisted prior to a `DnsItem` contract upgrade automatically migrate to the current `StateInit` address. Because `.bro` domains in active or ended auctions have `ownerAddress == null` on-chain until `FinalizeAuction` is executed, `fetchBroCollectionNftAddresses` must query both `owner_address=${walletAddress}` and collection-level `/nft/items?collection_address=${BRO_COLLECTION_RESOLVER}` so unfinalized auctions where `maxBidAddress == walletAddress` are discovered on-chain. Any persisted domain whose on-chain account state is not `active` (after a 45-second grace window for newly broadcast registrations) or where neither `isOwnedByMe` nor `isBidByMe` holds must be pruned via `removeDomain` rather than skipped, and optimistic registrations in `ExploreTab` must initialize `isAuctionActive: true, hasOwner: false, auctionEndTime: now + 300` so `MyDomainsTab` renders the auction/finalization UI instead of premature owner record controls.

### State Management & Selector Stability Rules (Zustand & React)

- **Stable Fallback References in Selectors:** Never use inline object/array literals as selector fallbacks (e.g. `foo ?? []` or `bar ?? {}`) and never invoke state methods that compute or allocate fresh collections inside selector functions (e.g. `state.getContactsList(network)`). Inline allocations produce new memory references on every selector pass, defeating `useShallow` / `useSyncExternalStore` equality checks and causing React to throw _"The result of getSnapshot should be cached to avoid an infinite loop"_ and _"Maximum update depth exceeded"_. Always subscribe directly to the raw slice state property with a module-level frozen fallback singleton (e.g. `state.contactsByNetwork[network] || EMPTY_CONTACTS_MAP`, `EMPTY_ARRAY = Object.freeze([])`, `EMPTY_OBJECT = Object.freeze({})`) and perform filtering or derivation inside `useMemo`.
- **Decouple Background Hydration from Subscribed State:** Do not place mutable slice state objects (e.g. `brotherhoodByAddress`, `jettonsByAddress`) in `useCallback` or `useEffect` dependency arrays of sync/hydration routines. Instead, access the latest state imperatively via `storeApi.getState()` (or `useWalletStoreApi().getState()`) to avoid circular invalidation feedback loops.
- **Change Guards in Slice Setters:** Guard slice mutation methods (e.g. `setBrotherhoodMemberData`, `setLocationContract`) against redundant updates. Check existing values before calling `set(...)` to prevent triggering spurious store change events.
- **No Side Effects or Setters in Render / useMemo:** Never invoke store setters, persistence helpers (e.g. `saveUsernameAddressMapping`), or storage writes directly inside `useMemo` or during the component render phase. Always defer side effects to `useEffect` or wrap in `queueMicrotask` to prevent React from throwing _"Cannot update a component while rendering a different component"_.
- **Persist Middleware Parity:** Whenever a slice is added to `partialize`, ensure it is also explicitly handled in `persist.merge(...)` within `createWalletStore.ts`. Otherwise, persisted data will be wiped and reset to initial state upon rehydration.
- **Safe BigInt Serialization in Store Tools & Modals:** When serializing arbitrary store slices or contract states (e.g. Jetton balances, Brotherhood credits, TVM stacks) to JSON for storage managers, debug inspectors, or clipboard exports, never use unhandled native `JSON.stringify`. Always use a BigInt-safe serializer replacer (`safeJsonStringify`) that converts `bigint` values to string to prevent uncaught `TypeError: Do not know how to serialize a BigInt` crashes.
- **Protected State Slices in Store Editors:** In low-level state exploration or storage management interfaces, strictly separate transient/cached data from critical authentication and key management structures. Mark slices holding private keys, mnemonic phrases, and wallet configurations (`savedWallets`, `auth`) as Read-Only / Protected to prevent accidental cryptographic corruption.
- **No Synchronous SetState in Effects for Derived or Cached State:** Never invoke `setState` synchronously within the root execution path of `useEffect` to mirror, reset, or populate locally available or cached data (e.g. contact book or cache lookups). Synchronous `setState` calls in effect bodies violate React 19 concurrent guarantees and trigger `react-hooks/set-state-in-effect` compiler errors. Instead, derive local or cached state synchronously using `useMemo` alongside asynchronous state (e.g. `effectiveAddress = localAddress || (asyncResolution?.key === currentKey ? asyncResolution.address : null)`), and restrict `setState` strictly to asynchronous completion callbacks (`setTimeout`, promise fulfillment) while guarding with cancellation flags.
- **React 19 SVG & Lucide Icon Typing Invariant:** In React 19, SVG HTML attributes type `aria-hidden` strictly as `Booleanish | undefined` (`boolean | 'true' | 'false'`). Declaring custom component icon prop interfaces with generic string types (e.g. `{ 'aria-hidden'?: string | boolean }`) is incompatible with Lucide's `LucideProps` / `LucideIcon` and triggers compiler error `TS2322`. Reusable tab, navigation, and button interfaces must type icon props cleanly as `LucideIcon | React.ComponentType<{ className?: string }>`.

### Animation, Motion, and Fluid UI Rules (Framer Motion & Zustand)

- **3-Way Animation Level Parity:** Always respect the active `animationLevel` (`none`, `performance`, `full`) from `usePreferences()` / `useAnimationSettings()`. When `none` (Disabled), suppress spring and layout transitions (`reducedMotion="always"`) to save battery and minimize CPU footprint on low-end devices. When `performance` (TMA/Mobile default), use lightweight opacity crossfades and rolling balance numbers. When `full` (Desktop/Rich default), enable full spring physics, layout shifts (`layout="position"`), and gesture overscroll.
- **Re-Render-Free Dynamic Values (No RAF setState):** Never use `requestAnimationFrame` loops with React `useState` / `setState` for animated balance tickers or rolling counters. Instead, use Framer Motion's `useSpring` and `useTransform` subscribed directly to the DOM element's `textContent` (e.g. `<AnimatedBalance />`) to update figures smoothly at 60fps without scheduling Virtual DOM component re-renders.
- **Optimistic Transaction Ingestion & Reconciliation:** Always append newly broadcast transfers (TON, Jettons, FI, Personal Tokens, Swaps) to `pendingTransactions` via `addPendingTransaction` immediately with a pending badge and optimistic balance calculation. Let the WebSocket streaming / on-chain event ingestion stream (`loadEvents`) automatically reconcile and prune the pending record once the block is indexed.
- **Zero-Redundant Routing & Background Sync:** Do not poll or trigger balance/event sync on window focus or tab visibility changes when WebSocket streaming is active. Rely exclusively on WebSocket streaming (`watchBalance`, `watchTransactions`), network reconnect (`window.online`), and explicit user pull-to-refresh. In store slices (`loadUserJettons`, `loadEvents`, `batchHydrateUniversal`), protect with 60s TTL guards against redundant route transitions (`/` <-> `/send`), allowing bypass only when `force = true`.
- **Time-Sliced In-Process Worker Fallback:** When offloading heavy BOC decoding or cryptographic hashing to Web Workers, always pair worker dispatch with an asynchronous, chunked fallback (e.g. `processAccountItemsAsync` in chunks of 5 yielding via `requestAnimationFrame` / `setTimeout(0)`) with an 8s timeout to eliminate main-thread UI freeze violations in fallback/test environments.
- **Horizontal Scroll Swipe Isolation & Peak-Pullback Cancellation Invariant:** Horizontal scroll strips (`DashboardActions`, `NftsCard`, `ScrollableTabBar`, `BottomNav`, filter chips) must never conflict with screen or sub-tab swipe navigation (`ScreenSwipeContainer`, `SwipeableSubTabs`). In addition to explicit `no-swipe` / `data-swipe-ignore="true"` markers, `shouldIgnoreSwipeStart` in `swipe-gesture-store.ts` automatically walks the DOM tree to ignore touches originating inside any horizontally scrollable ancestor (`scrollWidth > clientWidth + 4` with `overflow-x: auto | scroll | overlay`) or slider input. `WalletCardCarousel` must only capture horizontal swipes (`data-swipe-ignore="true"`) when `savedWallets.length > 1`. Furthermore, all swipe gesture handlers (`updateSwipeKinematics`) must track `peakAbsX` and instantaneous velocity (`velocityX`), immediately disarming (`isCanceled = true`) if the user pulls their finger back `>= 12px` toward the origin (`peakAbsX - absX >= 12`) or reverses velocity before releasing, ensuring the user remains on the current page when reversing a swipe without lifting their finger.

Always use Telegram's native `BiometricManager` (`init`, `requestAccess`, `updateBiometricToken`, `authenticate`) inside TWA, falling back to WebAuthn only on standard Web/PWA.

Always listen to `safeAreaChanged`, `contentSafeAreaChanged`, `fullscreenChanged`, `fullscreenFailed`, and `viewportChanged` events to update `--tg-safe-area-top` and `--tg-safe-area-bottom` so top headers and action buttons are never obscured by the phone status bar.

Always normalize router paths against `VITE_BASE` / `BASE_URL` (`/brotherhood/`) when evaluating root route vs sub-routes to avoid unintentional TMA minimization.
- **Modal History & Back-Stack Hygiene on Web vs TWA:** Never push or pop raw `window.history` entries (`window.history.pushState({ modalId })` / `window.history.back()`) for component modals on Web. In SPAs using TanStack Router, synthetic history mutations corrupt router internal state keys (`__TSR_key`, `__TSR_index`), and calling `window.history.back()` on modal unmount races with user navigations out of modals, firing `popstate` events that abort the transition and bounce users back. Reserve back-stack coordination strictly for Telegram's native `BackButton` via `showTelegramBackButton` / `handleGlobalBack()`, leaving Web modal dismissals to React state and Radix/Vaul ESC/backdrop handlers (`syncHistory: false` by default).
- **WebRTC & QR Scanner Video Containment:** Third-party camera and QR scanning libraries (e.g. `html5-qrcode`) inject unstyled video and canvas elements with hardcoded dimensions. Always contain them within an explicit aspect-ratio container with strict override utilities (`[&_video]:w-full! [&_video]:h-full! [&_video]:object-cover! [&_img]:hidden! [&_span]:hidden!`) and anchor scanner overlays using safe-area insets (`--tg-safe-area-top`, `--tg-safe-area-bottom`) to prevent viewfinder clipping and layout shifts.

Mini App interfaces must leverage Telegram WebApp native SDK bridge methods: `Telegram.WebApp.showScanQrPopup` for zero-friction QR code scanning with native OS camera permissions, and `Telegram.WebApp.readTextFromClipboard` for seed phrase or address pasting.
- **SPA History Stack Root Sentinel & Navigation Trapping:** In single-page applications with browser/hardware back-button support, relying on standard `popstate` handlers without a sentinel history entry allows the browser to traverse backward into prior auth/unlock screens or historical tabs. The root route (`/wallet`) must maintain an isolated root sentinel state (`{ isRootTrap: true }`) so that initial back-button actions remain trapped at the root, displaying an exit confirmation toast and requiring a second backpress within 2 seconds to close the app.
- **QR Code Offline Caching & Non-Bounceable Address Presentation:** In wallet receive interfaces, QR code rendering must not block on remote asset resolution or SVG drawing cycles. Rendered QR code SVGs must be cached locally in `localStorage` keyed by target address to provide immediate, zero-latency offline rendering. For V5R1 and smart wallets, receive views should present only the non-bounceable user-friendly address (`0Q...` on testnet, `UQ...` on mainnet, `bounceable: false`), eliminating confusing multi-format tabs for end-users.
- **Root Frame Display vs CSS Box Stripping (`display: contents`):** Animating CSS `opacity` or transforms with Framer Motion on elements with `display: contents` (e.g. `className="contents"`) fails to generate an element box in the browser render tree, causing child views (`<Outlet />`) to be invisible or omitted on initial load in Chromium/WebKit engines while sibling fixed elements remain visible. Root layout animation wrappers must always use a real container box (e.g. `className="min-h-screen w-full flex flex-col flex-1"`).
- **WebAuthn User Activation Gesture Invariant:** Calling WebAuthn credentials retrieval (`navigator.credentials.get`) inside unprompted `useEffect` on page mount without a direct transient user activation (gesture) causes modern browsers to reject or suspend the credential prompt until the user interacts with the document, creating a perceived UI hang. Auto-prompting biometrics on mount must be restricted to supported native environments (e.g. Telegram Mini App `BiometricManager`), while standard Web clients must focus the passcode input and trigger WebAuthn strictly via explicit user click actions.
- **Storage Hydration Guard Invariant:** When routing or gating views based on persisted authentication or wallet state (`isPasswordSet`, `isUnlocked`, `hasWallet`), the root application shell must strictly gate rendering on `state.isHydrated` from Zustand persist middleware in addition to core kit initialization (`!isWalletKitInitialized || !isHydrated`). Evaluating unhydrated state on initial mount causes premature redirects to onboarding or unlock routes before local storage is read.
- **Immediate App Update & Unblocked Service Worker Reload:** Service worker updates and automatic cache activations must never be blocked or deferred by background sync routines, polling tasks, or open informational/settings dialogs. `autoApplyUpdate()` must only postpone reloads when cryptographic message/transaction signing is actively in flight (`.signing-in-progress` or `[data-tx-signing="true"]`), and must trigger immediate page reloads via `controllerchange` listeners and `SKIP_WAITING` messages upon update installation.

### Wallet Security & Credential Hygiene Rules

- **Conditional Credential Persistence & Auto-Lock Opt-Out Invariant:** Never write unencrypted mnemonics or private keys to Web Storage (`localStorage`, `sessionStorage`, IndexedDB, cookies), and by default (`persistPassword === false`, Auto-Lock enabled) never persist `currentPassword` in Zustand `partialize`.
