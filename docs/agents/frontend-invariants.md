# Frontend, UI, State, Storage & Mobile/TWA Invariants

Consult this file whenever editing React components, hooks, Zustand stores, CSS/theming, modals, routing, QR codes, or Telegram Mini App integrations under `apps/wallet/` and `packages/`.

## React 19, Compiler & Zustand Selector Stability

- **React Compiler Purity & Manual Memoization:** Never call impure functions (`Date.now()`, `Math.random()`) in render bodies or `useMemo` callbacks (`react-hooks/purity`); initialize via `useState(() => Date.now())` or inside event handlers. When a `useMemo` depends on an optional-chained property (e.g. `fiAccount.data?.jettonBalance`), extract `const fiJettonBalance = fiAccount.data?.jettonBalance;` before `useMemo` and list `fiJettonBalance` in the dependency array (`react-hooks/preserve-manual-memoization`).
- **Stable Selector References:** Never return inline literals (`?? []`, `?? {}`) or freshly allocated collections (`state.getContactsList(network)`) inside Zustand selectors. Subscribe to raw slice state with module-level frozen singletons (`EMPTY_ARRAY = Object.freeze([])`, `EMPTY_OBJECT = Object.freeze({})`) and derive filtered lists in `useMemo`.
- **No Synchronous `setState` in Effects or Side Effects in Render:** Never call store setters or `localStorage` writes inside `useMemo` or render. Never call `setState` synchronously at the root of `useEffect` to mirror cached/local data (`react-hooks/set-state-in-effect`); compute local state via `useMemo` and restrict `setState` in effects to async callbacks guarded by cancellation flags.
- **Zustand Equality Bailouts & Hydration Decoupling:** Store actions invoked from effects/hydration (`saveOnChainUsername`, `saveDnsDomain`, `setBrotherhoodMemberData`, `setLocationContract`) must bail out (`return state;`) when the stored value is unchanged, and `useMemberProfiles`'s `enrichedData` `useMemo` must return `query.data` unchanged when no DNS fields differ (preventing React error `#185` infinite loops). Access mutable store state imperatively via `storeApi.getState()` inside background sync hooks rather than adding slice maps to effect dependency arrays.
- **Persist Middleware & Safe BigInt Serialization:** Every slice included in `partialize` must be merged in `persist.merge(...)` in `createWalletStore.ts`. Use `safeJsonStringify` for any JSON export or inspector handling `bigint` values, and keep `savedWallets` and `auth` slices read-only in storage debug tools.
- **React 19 Icon Prop Typing:** Type reusable component icon props as `LucideIcon | React.ComponentType<{ className?: string }>` (never `{ 'aria-hidden'?: string | boolean }`, which conflicts with React 19's `Booleanish` SVG attribute typing `TS2322`).

## 2D Theme × Palette, Layout & Interactive Controls

- **2D OKLCH Theme Binding & CSS Specificity:** Bind interactive controls (`Button`, `HoldToSignButton`, `SlideToSignButton`, `TxButton`, `Segmented`, `BottomNav`, `ScrollableTabBar`, `ToggleRow`, `Select`) to CSS theme tokens (`bg-primary`, `text-primary-foreground`, `border-primary`, `focus:ring-ring`, `bg-destructive`) instead of hardcoded `blue-500` or rainbow tab classes. In `App.css`, always scope palette blocks by both theme and palette (`[data-theme='...'][data-palette='...']`, never unscoped `:root[data-palette='...']`), and bind Liquid Glass variables with `html[data-glass='true'][data-theme][data-palette]` (specificity `(0, 3, 1)`).
- **Slide/Hold Controls, Toggle Switches & Contract Placeholders:** In `SlideToSignButton`, place the thumb (`shrink-0`) before the label (`flex-1 min-w-0 px-2.5`) without `"Slide to "` prefixes, unconditionally apply `w-full` on `SlideToSignButton` / `HoldToSignButton` / `TxButton`, and track drag via synchronous Pointer Events (`setPointerCapture`, `touch-none`). In toggle switches (`ToggleRow`, `CommentField`, `NetworkSettingsPanel`), use a `relative inline-flex items-center rounded-full p-0.5 ring-1 ring-inset` pill track with an explicit `<span />` thumb. In contract-mutating forms, keep `value` empty (`""`) until user input and show the current on-chain value in `placeholder`.
- **3-Way Animation Level & DOM-Direct Tickers:** Respect `animationLevel` (`none`, `performance`, `full`) from `usePreferences()`. Use Framer Motion `useSpring` + `useTransform` bound to `textContent` (`<AnimatedBalance />`) rather than `requestAnimationFrame` + `setState`. Never use `display: contents` (`className="contents"`) on animated root layout wrappers.

## Swipe Navigation, Modals & Router Back-Stack

- **Swipe Transform Isolation & Nav Bar Scroll Stability:** Never wrap `DashboardHeader`, sticky `ScrollableTabBar`, or fixed `BottomNav` in `transform: translate3d(...)` or `document.startViewTransition()`. `ScreenSwipeContainer` wraps only `<main>` in `NewLayout`, and `SwipeableSubTabs` applies `translate3d` only to the inner content pane. `ScrollableTabBar` scrolls horizontally via `container.scrollTo({ left, behavior: 'smooth' })` (never `scrollIntoView()`), and `BottomNav` persists `scrollLeft` across route mounts.
- **Horizontal Scroll Boundary Handoff & Pullback Cancellation:** `ScreenSwipeContainer` and `SwipeableSubTabs` evaluate `canTargetScrollHorizontally(target, direction)` so swipes inside horizontal strips (`NftsCard`, `DashboardActions`, filter chips) hand off to tab/screen navigation once the scroll container hits its left (`scrollLeft <= 4`) or right (`scrollLeft + clientWidth >= scrollWidth - 4`) boundary. `updateSwipeKinematics` tracks `peakAbsX` and cancels the swipe (`isCanceled = true`) if the user pulls back $\ge 12\text{px}$ toward the origin (`peakAbsX - absX >= 12`).
- **Modal History vs TanStack Router Navigation (`back-stack-manager.ts`):** Never call `window.history.pushState()` eagerly in `registerRouterBack()` (push `{ isRootTrap: true }` lazily in `handleRootExitConfirmation()`). In `unregisterBackCallback`, never call `window.history.back()` synchronously or overwrite `window.history.state` without spreading `...(window.history.state || {})` (preserving `__TSR_index` and `__TSR_key`). Always call `notifyRouterNavigation()` in `useNavigate()` and `ProtectedRoute`, defer `history.back()` via `setTimeout(..., 0)` guarded by navigation-suppression checks, and constrain mobile drawers with `max-h-[88dvh] overflow-hidden` and scrollable bodies (`overflow-y-auto min-h-0 flex-1`).

## Offline Image Caching, IndexedDB QR Storage & Security

- **3-Tier Image Cache, IndexedDB QR Cache & Non-Opaque Quota Guard:**
  1. `FallbackImage` uses (a) L1 `localStorage` Data-URL cache (`brotherhood_cached_image_data_v1`) for compact icons ($\le 48\text{ KB}$), (b) L2 IndexedDB Blob store (`brotherhood_offline_images_db`) + `CacheStorage` (`brotherhood-images`), and (c) Workbox runtime caches with `statuses: [200]` only.
  2. Never cache opaque cross-origin responses (`status === 0` / `mode: 'no-cors'`) in `CacheStorage` (Chromium pads each opaque entry by ~7 MB toward origin quota).
  3. Per-wallet Receive QR codes (`bro_receive_qr_v2_*` colorful SVG and PNG blobs in `ReceiveModal`) must be stored in IndexedDB (`brotherhood_offline_images_db`) + volatile L1 memory cache, never in `localStorage`. Receive views always display the user-friendly non-bounceable address (`0Q...` testnet / `UQ...` mainnet).
  4. `StorageManagerModal` (`clearRuntimeCacheStorage`) must purge runtime `CacheStorage` buckets, `FallbackImage` caches, and reset auth state on Nuclear Reset.
- **Credential Hygiene, Auto-Lock & Last-Wallet Reset:** Never persist unencrypted mnemonics or private keys. By default (`persistPassword === false`), never persist `currentPassword` in Zustand `partialize`; only persist and restore `currentPassword` in `createWalletStore` when the user explicitly disables Auto-Lock (`persistPassword === true`). Wrap `/create-wallet`, `/import-wallet`, and `/ledger` in `<ProtectedRoute>` checking `isUnlocked && Boolean(currentPassword)`. Removing the last wallet in `removeWallet` (or Nuclear Reset) must reset `state.auth` (`isPasswordSet = false`, `isUnlocked = false`, `currentPassword = undefined`) and clear biometrics so the app returns cleanly to `/welcome`. When unlocking from `UnlockScreen`, check `hasWallet` before navigating to `/wallet`. Never show floating banners (`PwaInstallBanner`) on onboarding/auth routes.
- **SimpleX `simplex:/` Custom Scheme & Universal Profile `username`:** Convert SimpleX/ThatsApp links to canonical `simplex:/...` URIs via `toSimplexCustomSchemeUri` and trigger `simplex:`, `briar:`, and `tg:` URIs via anchor click in `openSocialLink` so Android shows the native app chooser (avoiding `https://simplex.chat` App Link hijacking). Normalize `FiWallet` `profile.username` via `normalizeProfileUsernameInput`, display via `formatProfileUsernameDisplay` (no `@` prefix on URLs or `.bro` domains), and open via `openMemberContact`.
- **Telegram Mini App (TWA) Native Bridges:** Inside TWA, use `Telegram.WebApp.BiometricManager` (never WebAuthn `navigator.credentials.get`, which requires a direct user click on Web), `showScanQrPopup` for QR scanning, `readTextFromClipboard` for clipboard reads, and eager `BackButton` listeners normalized against `VITE_BASE` (`/brotherhood/`). Bind `--tg-safe-area-top` and `--tg-safe-area-bottom` from Bot API 8.0+ safe-area events.
- **ActonScan Unconfirmed Tx Routing & Service Worker Updates:** On ActonScan, route unconfirmed broadcast transactions (which only have an external-in message BOC hash) to `/address/:addr#activity`, reserving `/tx/:hash` for mined transaction hashes. In `autoApplyUpdate()`, only defer Service Worker reloads when `.signing-in-progress` or `[data-tx-signing="true"]` is active.
