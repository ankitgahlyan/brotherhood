# Tolk Smart Contracts & Acton Invariants

Consult this file whenever editing `contracts/src/**/*.tolk`, `contracts/tests/**`, `contracts/scripts/**`, `wrappers-ts/**`, or `Acton.toml`.

## Architecture & Compilation Rules

- **Modular Structs & Fail-Fast Entrypoints:** Keep struct and message definitions in per-contract files (`messages.tolk`, `storage.tolk`) with shared primitives in `contracts/src/common/`. Assert preconditions at the very top of message handlers.
- **Centralized Constants & Non-Transitive Tolk Imports:** All global protocol constants, emission values, auction timings, and canonical addresses (`FI_ADDRESS`, `BRO_COLLECTION_RESOLVER`, `BRO_TREASURY_ADDRESS`, `DAO_PROXY_ADDRESS`, `ZERO_ADDRESS`) live exclusively in `contracts/src/common/constants.tolk` (synced with `apps/wallet/src/lib/brotherhood/config.ts`). Tolk imports are strictly file-scoped (non-transitive): any file referencing global constants must directly `import "@contracts/common/constants"`.
- **Unified Global Exit Codes (`enum Errors`):** Tolk top-level `enum` declarations share a single compilation namespace. Declare all custom exit codes exclusively in `contracts/src/common/errors.tolk` (disambiguating domain codes such as `DnsNotOwner = 401` vs `NotOwner = 73`, `DnsIncorrectSender = 424` vs `IncorrectSender = 700`) and directly `import "@contracts/common/errors"`.
- **No Custom Public On-Chain Libraries (TON Global Version 15+):** Publishing public masterchain libraries (`SETLIBCODE(code, 2)` / `acton library publish`) from regular accounts is prohibited by TON validators (`action_result_code = 46`). Always use deterministic minimal proxies (`Base*`) or embedded code cells.
- **Generated TypeScript Wrappers (`wrappers-ts/*.gen.ts`):** Treat `wrappers-ts/` as generated output (`[wrappers.typescript]` in `Acton.toml`). Whenever contract ABIs or bytecodes change, run `acton build && acton wrapper` rather than hand-editing `.gen.ts` files.

## Deterministic Proxies & Upgradability

- **Deterministic Proxy Bytecode & `@method_id(2223)` Storage Migration:** Minimal proxies (`BaseFiWallet`, `BasePersonalMinter`, `BaseLocation`, `BaseFollowing`) used for deterministic child address derivation must never self-import their own compiled bytecode or serialize full target storage structs (`FiWalletStore`, `PersonalStore`, `LocationStore`, `FollowingStore`). Proxies verify sender + target code cell, call `setCodePostponed`, replace `c3` via `setTvmRegisterC3`, and invoke target migration `@method_id(2223)` (`migrate*FromBase`). Target contracts must keep `@method_id(2223)` in their compiled dictionary. Whenever any `Base*.tolk` changes, sync its `code_boc64` to its `base-*-code.tolk` helper and `wrappers-ts/Base*.gen.ts`.
- **Acyclic `BasePersonalWallet` & Method 0 Re-entry:** `BasePersonalWallet` never embeds `PersonalWallet.code`. `InternalTransferStep` delivers `latestWalletCode`, gated by `((msg.jettonAmount == grams("1")) | msg.transferredAsCredit) & (msg.latestWalletCode != null)` (throwing `Errors.NotOnboardedWallet`). It installs code via `setCodePostponed`, replaces `c3`, and executes `0 CALLDICT`. Sync `getBasePersonalWalletCode()` in `contracts/src/personalMinter/personal-wallet-code.tolk` and `wrappers-ts/BasePersonalWallet.gen.ts` whenever `BasePersonalWallet.tolk` changes.
- **Personal Token & Wallet Monotonic Schema Upgrades:** `PersonalMinter` and `PersonalWallet` maintain monotonic `version: uint10 = 1`. In contracts with a trailing `storage.save()` at the end of `onInternalMessage`, `Upgrade` handlers must never early-`return;` before persisting mutated fields. `HotUpgrade` authenticates `in.senderAddress == storage.minterAddress` (or admin/parent). Peer `Upgrade` verifies `in.senderAddress == autoAddrPriWallet(msg.sender).calculateAddress()`.
- **Instant `FossFiWallet` Upgrade Propagation & Gas Guard:** `FossFiWallet` propagates `Upgrade` across `maps.invited` only when `store.version < msg.walletVersion`. Each forwarded message carries `0.1 TON` (`SEND_MODE_PAY_FEES_SEPARATELY | SEND_MODE_IGNORE_ERRORS`), halting iteration if `contract.getOriginalBalance() < 0.3 TON` (`0.2 TON` reserve + `0.1 TON` forward cost). Accept empty messages (`in.body.remainingBitsCount() == 0`) with an early return for plain TON top-ups.

## Credit, Bounce Recovery & `.bro` DNS

- **3-Decimal Fixed-Point Multiplier & Manual `creditNeed`:** `FiWalletStore.multiplier` (`uint16`) uses `MULTIPLIER_SCALE = 1000` (`1000 = 1.000x`, range `0.001x`–`65.535x`). `creditNeed` is modified only via `SetLoanRequirement` (never auto-replenished on `Payback`). When `multiplier <= 1000`, `creditMaturity` may be `0`; when `multiplier > 1000`, `SetLoanRequirement` requires `effectiveMaturity > blockchain.now()` and `BuyCredit` rejects when `blockchain.now() >= store.creditMaturity`. Frontend normalizes via `normalizeOnchainMultiplier` (`raw / 1000`) and encodes via `encodeOnchainMultiplier`.
- **`RichBounce` Reference Preservation:** Whenever a bounce handler reads child cell references from `RichBounceBody.originalBody` (e.g. `MintNewJettons.internalTransferMsg` or `BidBroDomain` / `RenewBroDomain` exceeding 256 bits in `FossFiWallet` and `FossFi`), dispatch with `BounceMode.RichBounce` (not `RichBounceOnlyRootCell`, which strips child refs and causes TVM cell underflow `exit_code = 9` or `63`) and handle `0xfffffffe` (`RichBounceBody`) in `onBouncedMessage`.
- **DNS Item 1023-Bit Root Cell Limit:** In `DnsItem` (`ItemStorageInitialized`), keep root storage $\le 855$ bits by isolating extension fields (`fiMinterAddress`) in the 4th reference slot (`extra: Cell<ItemExtra>? = null`), preventing TVM `exit_code = 8` (_"Cell overflow"_) when `ownerAddress` is assigned.
- **DNS Owner Guard vs Null Dereference:** In `DnsItem.tolk`, check `storage.ownerAddress != null && in.senderAddress == storage.ownerAddress` instead of force-unwrapping `storage.ownerAddress!` (which aborts with TVM `exit_code = 7` during active/unfinalized auctions).
- **`.bro` FI Auction Finalization Guard:** Bypass legacy TON DNS post-auction auto-completion when `storage.getFiMinterAddress() != null` so `FinalizeAuction` can unpack the winning bid, assign domain ownership, and send `DnsAuctionFinalized` to `FossFi` (burning winning FI and routing `0.5 TON` to Treasury).
- **Tolk Custom Map Alias Serialization (`toDnsRecordsCell`):** Mutating a custom-packed map alias (`type DnsRecords = map<uint256, cell>` with 8-bit `0x00` TEP-64 prefix) via `.set()` / `.delete()` or `= []` decays its static type to `map<K, V>`. Always serialize via `dnsRecords.toDnsRecordsCell()` instead of `.toCell()` to preserve the 8-bit prefix and prevent `exit_code = 9`.
- **TEP-64 Collection/Item Metadata & TEP-81 `get_auction_info`:** `DnsCollection` serializes off-chain content inline (`0x01` + ASCII URI via `makeBroOffchainContentCell`, never double-wrapped in a child ref). `DnsItem` preserves on-chain `"name"`, `"image"`, and `"description"` keys across `initialContent` and `ChangeDnsRecord`. `unpackAuction` returns `createAddressNone() as address` (`b{00}`) instead of `null` when `auction == null`.
- **Deterministic `StateInit` Timestamps:** Contracts with deterministic addresses (`DnsCollection`) must initialize timestamp fields to `0` in `StateInit.data` (`deploymentTime: 0`) and set `blockchain.now()` lazily inside the initial message handler (`FillUp { queryId: 1 }`).

## Acton Testing & Deployment Scripts

- **`testing.setNow()` Before Actor Creation:** In Tolk tests, call `testing.setNow(AUCTION_START_TIME + 100)` **before** `testing.treasury()` or `newActor()` to avoid 52-year storage fee calculation aborts (`exit_code = -669`).
- **Use `build("<Contract>")` Instead of `@gen/*.code`:** Tests (`contracts/tests/`) and scripts (`contracts/scripts/`) must load contract code via `build("<Contract>")` from `@acton/build` rather than gitignored `@gen/<Contract>.code`.
- **Emulation Verification Before Broadcast:** Verify contract flows with `acton run deploy-emulation` (and `acton run verify-personal` for personal tokens) before live `--net` broadcasts.
- **`scripts.wallet()` in `--fork-net` vs `--net`:** Under `--fork-net`, `scripts.wallet(name)` returns a synthetic treasury address. Sender-authenticated scripts (`deploy-personal.tolk`, `destroy-personal.tolk`) must resolve the sender via `promptJettonAddress("PERSONAL_ADMIN_ADDRESS", ..., wallet.address)` and send from that address (`net.send(admin, ...)`).
